# CRM المحترف: الفرونت

## التشغيل

```powershell
npm install
npm run dev
```

شغّل الباك أولاً. ملف Vite الحالي يمرر `/api` إلى `https://localhost:7271`؛ شغّل ملف تعريف `https` في المشروع. في حال تعذّر اتصال المتصفح بـSwagger بسبب شهادة HTTPS المحلية، وثّق الشهادة باستخدام `dotnet dev-certs https --trust`، أو شغّل ملف تعريف `http` وافتح Swagger على `http://localhost:5077/swagger`. بعد تغيير `.env.local` أعد تشغيل Vite.

عنوان الـAPI هو `VITE_API_URL`. يقبل العميل عنوان الخادم `https://localhost:7271` أو عنوان API كاملاً ينتهي بـ`/api`؛ الإعداد المحلي يستخدم `/api` عبر Vite proxy إلى `https://localhost:7271`. الاتصال المباشر يتطلب أن يسمح CORS بعنوان الواجهة؛ الخادم يسمح حالياً بـ`http://localhost:5173` فقط. تأكد من `VITE_USE_MOCKS=false` للاتصال بالباك؛ فعّلها فقط للتطوير دون الباك.

## عقد تكامل الواجهات

- مصدر تفاصيل العمليات السبعة وحقولها وقواعد التحقق هو ملف المواصفات المرفق للمشروع. أرسل أسماء JSON وquery parameters بصيغة camelCase، وأرسل المصفوفات بمفاتيح متكررة.
- تسجيل الدخول: `POST /auth/login` يستقبل `accountName` و`password`. خزّن `token`، وأرفق `Authorization: Bearer <token>` بكل الطلبات عدا login. عند أي `401` امسح الجلسة وارجع إلى صفحة الدخول. لا يوجد refresh endpoint؛ تسجيل الخروج محلي.
- الموظفون: `GET /users` يقبل فلاتر `pageNumber`, `name`, `accountName`, `email`, `isActive`, `roleId`, و`departmentId`. أرسل `roleId` و`departmentId` كـUUIDs من القوائم دون تحويلها لأرقام. تعرض القائمة السابق/التالي وفق `page.hasNextPage` فقط، بلا أرقام صفحات أو إجمالي. معرّف الموظف قيمة داخلية لا تعرضها الواجهة؛ رُصد في استجابة الباك الفعلية بصيغة UUID رغم أن المواصفة السابقة ذكرت رقماً. يحتفظ به العميل كـ`string | number` للروابط فقط.
- تفاصيل الموظف: `GET /users/{id}` يعيد الصلاحيات بالأسماء؛ حمّل `Departments` و`Roles` من `/lookups` وطابق الأسماء مع المعرّفات عند فتح نموذج التعديل.
- إنشاء وتعديل الموظف: `POST /users` موثق بأنه يعيد معرّفاً رقمياً خاماً، لكن العميل يقبل أيضاً UUID كنص لمطابقة استجابة الباك الفعلية. قد تكون `permissions` غير موجودة. قواعد التحقق والرسائل غير المؤكدة تُترك للخادم. `PUT /users/{id}` يعيد `204 No Content`؛ لا تحاول قراءة JSON من جسم فارغ. لا يغيّر هذا المسار كلمة المرور.
- القوائم: `GET /lookups` يدعم `Departments`, `Roles`, `Tracks`, و`LeadStatuses`. معرّفات هذه القوائم UUID؛ استخدمها كما وردت ولا تحوّلها لأرقام.
- جهات الاتصال: `GET /contacts` يقبل `trackId`, `leadStatusId` و`tagIds` المتكررة، وكلها UUID. المسارات وحالات العملاء تُحمّل من `/lookups`؛ لا توجد حالياً قائمة وسوم ضمن `LookupType`، لذا يتطلب فلتر الوسوم UUID معروفاً. شكل الاستجابة وحقول العناصر لا تزال غير مؤكدة؛ يعرض الفرونت حقول العنصر كما وردت دون افتراض أسماء أو بنية داخلية.
- أخطاء الخادم لها الشكل `{ "status": number, "message": string }`. اعرض `message` كما هو. `401` من JWT و`422` من محدد محاولات الدخول و`204` من تعديل المستخدم قد تعود دون جسم؛ اقرأ النص أولاً ولا تستدع `json()` دون تحقق.

## عناصر غير مؤكدة أو غير مشمولة

- `ContactsPageDto` وعناصر جهات الاتصال غير موثقة بالكامل. النوع والمواءمة مع الاستجابة معزولان في ميزة contacts، ولا تُبنى أعمدة على حقول مفترضة.
- قواعد التحقق الخاصة بإنشاء المستخدم وتكرار البريد/اسم الحساب غير مؤكدة؛ اعرض رسالة الخادم ولا تضف قيوداً تخمينية.
- وحدات `expiresIn` ومصدر قائمة الوسوم غير مؤكدة؛ لا توجد قائمة وسوم في `LookupType` الحالي.
- الحملات والتوجيه الأكاديمي والمشاكل والإشعارات والتواصل وتغيير كلمة المرور ليست ضمن نقاط النهاية السبعة في هذه المواصفة؛ تبقى واجهاتها غير متاحة ولا ترسل طلبات غير موثقة.
- ملفات المواصفات قد توصي بتغييرات للباك إند؛ لا تُطبقها من الفرونت.
- عند اختبار API الفعلي، استخدم `VITE_USE_MOCKS=false`. وضع MSW يدعم تسجيل الدخول والمستخدمين محلياً فقط؛ لا يوجد mock لجهات الاتصال.

## أوامر مفيدة

- `npm run lint` : فحص الكود وقواعد الحدود بين المجلدات.
- `npm run typecheck` : فحص TypeScript.
- `npm run build` : بناء نسخة نهائية.
- `npm run format` : تنسيق ملفات `src`.

## قواعد العمل

اقرأ `docs/conventions.md` قبل إضافة ميزات جديدة.

## ملاحظات

- `.env.local` للإعدادات الشخصية ولا يُرفع على Git. القالب في `.env.example`.
- يرسل الفرونت عبر Vite proxy إلى `https://localhost:7271` في إعداد التطوير الحالي.
- واجهة حساب `admin` قد تعرض مسارات إضافية لأغراض العرض، لكن ذلك لا يمنح صلاحيات على بيانات الـAPI؛ يجب أن يسمح الخادم بالطلبات.
