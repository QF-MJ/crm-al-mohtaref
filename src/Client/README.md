# CRM المحترف: الفرونت

واجهة React + TypeScript مبنية على Vite، وتتصل بـ ASP.NET Core API. هذا الملف يشرح التشغيل، ونموذج الصلاحيات، وطريقة الربط مع الباك.

## التشغيل

```powershell
npm install
npm run dev
```

شغّل الباك أولاً (بروفايل `https` على `https://localhost:7271`). يمرّر Vite كل طلب يبدأ بـ`/api` إلى الباك، فلا نحتاج CORS ولا نثق بشهادة HTTPS المحلية. بعد أي تغيير في `.env.local` أعد تشغيل Vite.

- `VITE_API_URL=/api` (الافتراضي): المرور عبر proxy.
- `VITE_API_URL=https://localhost:7271` أو `.../api`: اتصال مباشر (يتطلب شهادة موثوقة وسماح CORS).
- `VITE_USE_MOCKS=true`: تشغيل MSW للتطوير دون باك (الحسابات التجريبية أدناه).

## نموذج الصلاحيات

الباك لا يعرف أدواراً مثل «Admin» أو «SalesManager». كل مستخدم يملك صفوف `UserPermission`، كل صف = (قسم + دور)، والقرار يُتخذ من هذه الأزواج في:

- `AuthorizePermisionsAttribute` على الـqueries/commands.
- `GetUsersQueryHandler` و`GetUserQueryHandler` (تقييد النطاق بالقسم).
- `LoginCommandHandler` (يرسل الأزواج مع التوكن).

لذلك `src/permissions/access.ts` يبني «قدرات» من الأزواج نفسها، دون اختراع أدوار:

| القدرة | القاعدة الفعلية في الباك |
|---|---|
| `account.view` | أي مستخدم مسجّل: `GET /api/users/{id}` لحسابه |
| `users.view` | **قرار المنتج: `مدير` + `الإدارة` فقط** (الباك يسمح تقنياً لأي مدير بموظفي قسمه فقط) |
| `users.create` / `users.update` | `مدير` + قسم `الإدارة` فقط |
| `contacts.view` / `contacts.filter` | `مدير` + `الإدارة` أو `مدير` + `المبيعات` |
| `modules.preview` | وحدات لم تُطلق في الباك بعد: تُعرض صفحة توضيحية بدل 403 |

قواعد واجهة إضافية:

- **قائمة الموظفين وملفاتهم وصلاحياتهم تظهر للأدمن فقط** (`مدير` + `الإدارة`). لإرجاعها لمديري الأقسام لاحقاً: في `src/permissions/access.ts` بدّل `return isAdmin` إلى `return isManager` في حالة `users.view` — الباك يدعم النطاق بالقسم عبر `departmentId`.
- الموظف العادي (ومدير القسم غير الإداري) بلا وحدات بيانات في الباك حالياً، لذلك يرى لوحة التحكم وحسابه وصلاحياته فقط (مدير المبيعات يرى العملاء أيضاً).
- إخفاء العناصر في الواجهة للـUX فقط؛ الحماية الفعلية على الباك.

أسماء الأقسام والأدوار يجب أن تطابق `SeedRules.Lookups` حرفياً: `الإدارة`, `المبيعات`, `التسويق`, `خدمة العملاء`, `التوجيه الأكاديمي` — و`موظف`, `مدير`.

## الوضع الليلي

- زر للتبديل في الترويسة وشاشة الدخول (`components/common/ThemeToggle.tsx`)، والاختيار يُحفظ في `localStorage` بمفتاح `crm-theme`.
- الافتراضي يتبع تفضيل النظام (`prefers-color-scheme`)، ويُطبَّق قبل أول رسم عبر سكربت صغير في `index.html` لتفادي وميض الوضع الفاتح.
- الصفحات مكتوبة بأدوات ألوان ثابتة (`bg-white`, `text-slate`, `border-slate`)، لذلك `src/styles/theme.css` يعيد تعيين هذه الأدوات داخل `.dark` بدل تكرار `dark:` في كل عنصر. أي واجهة جديدة تستخدم ألواناً ثابتة جديدة قد تحتاج سطراً هناك.

## الجلسة والاتصال

- `POST /api/auth/login` يرجّع `token`, `expiresIn` (تاريخ ISO وليس ثواني), `userId` (Guid), `fullName`, `permissions`.
- لا يوجد `refresh` ولا `logout` في الباك: الخروج محلي، والتوكن منتهي الصلاحية يُكتشف من تاريخ `expiresIn` قبل إرسال الطلبات.
- أي `401` خارج تسجيل الدخول يمسح الجلسة وكاش React Query ويعيد المستخدم إلى صفحة الدخول.
- معرّفات المستخدمين والأقسام والأدوار والدورات وحالات العملاء كلها Guid (وليست أرقاماً).
- `PageDto` لا يحمل إجمالي النتائج: التنقل سابق/تالي عبر `hasNextPage` فقط. رقم الصفحة يُتتبع محلياً، و`page.pageNumber` القادم من `/contacts` غير موثوق (يرسل حجم الصفحة بدلاً من رقمها).

## نقاط النهاية المستخدمة

| العملية | المسار |
|---|---|
| تسجيل الدخول | `POST /auth/login` |
| القوائم | `GET /lookups?include=Departments&include=Roles...` |
| قائمة الموظفين | `GET /users` |
| ملف موظف | `GET /users/{id}` |
| إضافة موظف | `POST /users` |
| تعديل موظف | `PUT /users/{id}` |
| العملاء | `GET /contacts` |

بقية الوحدات (الحملات، التوجيه الأكاديمي، المشاكل، الإشعارات، التواصل، تغيير كلمة المرور) تعرض صفحة «غير متاح» ولا ترسل أي طلب، لأن الباك لا يوفر نقاط نهاية لها بعد. أُزيلت النسخة غير القابلة للتشغيل من واجهة الحملات لمنع انحرافها عن العقد.

## بيانات تجريبية

الباك يزرع البيانات عند التشغيل في وضع التطوير، وكلمة المرور للجميع `12345678` (تُستخدم للدخول فقط):

| الحساب | الصلاحية |
|---|---|
| `admin` | `مدير` / `الإدارة` — كل الصفحات والتعديلات |
| `user01` … `user24` | أزواج قسم/دور حسب التوليد؛ كل حساب بدور `مدير` يرى موظفي قسمه |

حسابات MSW (`VITE_USE_MOCKS=true`) بنفس كلمة المرور: `admin`, `sales`, `salesemp`, `marketing`, `support`, `academic`.

## الأوامر

- `npm run dev`: تشغيل التطوير.
- `npm run typecheck`: فحص TypeScript.
- `npm run lint`: فحص الكود وقواعد الحدود بين المجلدات.
- `npm run build`: بناء الإنتاج.
- `npm run format`: تنسيق `src`.

## البنية

```
src/
  api/            axios + interceptors + أخطاء موحّدة
  app/            التطبيق، الـproviders، الراوتر والحراس
  components/     ui + common (حالات فارغة/خطأ/تحميل، ترقيم صفحات)
  features/       auth, users, clients, lookups + وحدات «غير متاحة»
  layouts/        AuthLayout وAppLayout
  permissions/    نموذج القدرات المبني على أزواج (قسم + دور)
  stores/         جلسة المستخدم (Zustand + persist)
  i18n/           ar / en
```

قواعد العمل داخل المجلدات في `docs/conventions.md`، وبعضها مفروض عبر `.oxlintrc.json` (مثل الاستيراد عبر `index.ts` للميزات، ومنع `axios` خارج `src/api`، ومنع اتجاهات RTL المكتوبة يدوياً).
